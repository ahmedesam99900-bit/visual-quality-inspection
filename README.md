# Visual Quality Inspection

An image-based visual inspection project focused on the HC-SR04 modules
shown in the VisA PCB1 dataset.

The intended use case is to help an operator identify visible product
defects under controlled imaging conditions.

**Current status:** Dataset exploration, file auditing, and a custom
draft split are complete. YOLO annotation preparation is the next step.
No inspection model has been trained or evaluated yet.

## Planned Pipeline

1. Upload an image and check whether it can be inspected.
2. Locate the supported product using a custom YOLO detector.
3. Extract and preprocess the inspection region.
4. Apply a product-specific PatchCore anomaly model.
5. Display the inspection decision, anomaly score, and anomaly map.

The inspection region must include the module and its connector pins.
Crop settings and image-orientation handling are still under review.

## Dataset

The project uses the PCB1 category of
[VisA](https://github.com/amazon-science/spot-diff).

The local audit confirmed:

- 1,004 normal images and 100 anomalous images.
- Image dimensions of 1404 × 1070 pixels.
- 100 readable, nonempty anomaly masks with matching dimensions.
- No exact duplicates based on decoded RGB pixels and image dimensions.

This audit does not establish independence between similar images
or different photographs of the same physical item.

### Draft Split

| Split | Normal | Anomalous |
|---|---:|---:|
| Training | 804 | 0 |
| Validation | 100 | 40 |
| Test | 100 | 60 |

The manifest is stored in `splits/pcb1_v1_draft.csv`.

This is a custom development split, not the official benchmark protocol.
Reviewed samples are excluded from the draft test set. Independence
between the splits requires further review.

PatchCore will use normal training images to build its memory bank.
Validation data will support preprocessing and threshold selection.
Test data is reserved for final evaluation and must not be used to
train either model or tune the pipeline.

YOLO requires whole-product bounding boxes. The existing defect masks
are not a substitute for those annotations. YOLO annotation preparation
has not started yet.

## Available Scripts

| Script | Purpose |
|---|---|
| `src/audit_pcb1.py` | Audit image readability, masks, and exact duplicates |
| `src/preview_pcb1.py` | Generate a contact sheet and record inspected samples |
| `src/preview_pcb1_mask.py` | Overlay a ground-truth defect mask |
| `src/create_pcb1_split.py` | Generate the reproducible draft split |

The split script uses `outputs/pcb1_preview_samples.csv`, generated by
the contact-sheet script, to reserve reviewed samples for development.
Additional previously reviewed samples are recorded in the split script.

The split script intentionally refuses to overwrite an existing manifest.
The committed draft split can be inspected without rerunning the script.

## Development Environment

Development uses Python 3.12 in a virtual environment managed with uv.

- CPU laptop: development and planned inference benchmarking.
- RTX 3060 desktop: computationally intensive model preparation.

Expected dataset location:

```text
data/visa/pcb1/image_anno.csv
data/visa/pcb1/Data/Images/
data/visa/pcb1/Data/Masks/
```

With the existing environment and dataset available, run the audit from
the repository root:

```powershell
.\.venv\Scripts\python.exe .\src\audit_pcb1.py
```

This command uses the project's virtual environment directly.

Datasets, model weights, generated outputs, and the virtual environment
are excluded from version control.

- Image-level anomaly detection.

No model performance results are available yet.

## Scope and Limitations

- Initial support is limited to the product and imaging conditions
  represented by PCB1.
- Arbitrary circuit boards and unrestricted camera conditions are outside scope.
- Visual inspection does not establish electrical or functional safety.
- An anomaly score is not a calibrated defect probability.
- An anomaly map highlights departures from normal appearance; it does not
  independently establish a manufacturing defect.
- PatchCore does not automatically identify the defect category.
- The planned application must return a cannot-inspect result for unsuitable
  inputs rather than treating them as acceptable products.
- Video processing, tracking, counting, and user-triggered model training
  are outside the current scope.
